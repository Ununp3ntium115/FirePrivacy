# Coverage of the original Fire Privacy concepts

Audit date: October 5, 2026. Candidate inspected: `e70799a88b9b3d84bc30d3ecc4129af0196e2f84`.

**The current app implements a local report MVP, not every concept in the original repository.** Its useful workflow is import → inspect recorded activity → follow settings guidance → export or delete. The original vision also includes a signed knowledge base, richer analysis, preventive filtering, and optional private AI; those capabilities are absent from this candidate.

Implementation below means source exists and is wired into the current app. It does not mean a feature passed physical-device validation, Apple review, or release. This is a read-only feature audit, not a new scope decision or an instruction to abandon the App Store release.

## Baseline and evidence

The baseline is the original `main` commit `f95824d4fe734028998edea612a9d05d33d45111`, before the README and privacy architecture were rewritten around the smaller MVP:

- [Original README](https://github.com/Ununp3ntium115/FirePrivacy/blob/f95824d4fe734028998edea612a9d05d33d45111/README.md): historical visibility, signed knowledge-base matching, guided control, URL filtering, private explanation, editions, and the claimed Gate 1 feature list.
- [Original privacy architecture](https://github.com/Ununp3ntium115/FirePrivacy/blob/f95824d4fe734028998edea612a9d05d33d45111/PRIVACY-ARCHITECTURE.md): network ledger, retention, encryption, hostile input, AI boundaries, and accuracy promises.
- [Original security document](https://github.com/Ununp3ntium115/FirePrivacy/blob/f95824d4fe734028998edea612a9d05d33d45111/SECURITY.md): dataset trust, evidence hashing, confidentiality, logging, and cryptography requirements.
- [Original contributing instructions](https://github.com/Ununp3ntium115/FirePrivacy/blob/f95824d4fe734028998edea612a9d05d33d45111/CONTRIBUTING.md): deterministic versioned rules, neutral vendor classifications, network disclosure, and required checks.
- [Original .gitignore](https://github.com/Ununp3ntium115/FirePrivacy/blob/f95824d4fe734028998edea612a9d05d33d45111/.gitignore): the fifth file in that commit; it is development/signing-file guidance, not a feature specification.

That original `main` tree contained no application source despite its “Gate 1 is implemented” prose. This audit also inspected the separate `claude/fire-privacy-ios-spec-engijr` branch at `2cc9ba1207124fd3930b5a996d9eb541063afa6e`, particularly its [release gates](https://github.com/Ununp3ntium115/FirePrivacy/blob/2cc9ba1207124fd3930b5a996d9eb541063afa6e/Documentation/RELEASE-GATES.md), [data dictionary](https://github.com/Ununp3ntium115/FirePrivacy/blob/2cc9ba1207124fd3930b5a996d9eb541063afa6e/Documentation/DataDictionary/DATA-DICTIONARY.md), and [capability-bridge ADR](https://github.com/Ununp3ntium115/FirePrivacy/blob/2cc9ba1207124fd3930b5a996d9eb541063afa6e/Documentation/ADR/ADR-010-capability-bridges-are-stubbed.md). Its separate modules and stubbed bridges are not linked into the current app and do not establish current functionality or a tested earlier release.

## Original main: feature coverage

| On-device analysis; no accounts, ads, resale, or telemetry | Implemented in the candidate | [Core package](../Package.swift), [app model](../Apps/FirePrivacyApp/AppModel.swift), [Trust Center](../Apps/FirePrivacyApp/TrustSettingsViews.swift), and [privacy source guard](../Tests/PrivacyRegression/no-network-in-local-analysis.sh). No network or advertising SDK is linked. Browser links and user-selected share destinations are disclosed. The source guard is not a runtime network trace. App Store pricing and publisher practices remain external obligations. |
| Import Apple's exported NDJSON | Implemented for a limited supported schema | [ReportImporter](../Sources/FirePrivacyCore/ReportImporter.swift) and [bounded file access](../Apps/FirePrivacyApp/ReportFileIO.swift). Supports `networkActivity` with `bundleID` or an unambiguous accessor, and `access` sensor records with an accessor. Exported hits and timestamp text are retained. Unsupported lines are skipped with notes; real current iPhone/iPad export compatibility remains untested. |
| Normalize app/domain/sensor activity | Partial | Bundle IDs, ASCII host normalization, counts, sensor categories/kinds, and timestamps exist in [Observation](../Sources/FirePrivacyCore/PrivacyReport.swift). Website context, reported owner, `domainType`, `initiatedType`, and `domainClassification` are not preserved; there is no public-suffix/registrable-domain or Unicode-display normalization. Sensor totals are explicitly event-record counts, including begin/end pairs, rather than unique access counts. |
| Dashboard, app details, domain details, search, and demo | Implemented | [Overview](../Apps/FirePrivacyApp/OverviewView.swift), [evidence views](../Apps/FirePrivacyApp/EvidenceViews.swift), and [synthetic demo](../Sources/FirePrivacyCore/DemoReport.swift). Views describe exported activity, not live monitoring or installed-app inventory. |
| Deterministic evidence-backed findings | Partial | [PrivacyReport.findings](../Sources/FirePrivacyCore/PrivacyReport.swift) generates a few descriptive domain/sensor summaries with supporting observation UUIDs. It has no versioned rule registry, vendor-informed inference, severity/confidence model, or structured observed-fact/inference/uncertainty objects. The current finding mechanism is a minimal descriptive implementation of this broader concept. |
| Signed local knowledge base and domain/vendor classifications | Not implemented | Current [package targets](../Package.swift) contain only `FirePrivacyCore` and its tests. There is no bundled vendor dataset, matcher, classification source/review model, or knowledge-base service. The [domain view](../Apps/FirePrivacyApp/EvidenceViews.swift) correctly states that owner/purpose are not verified. |
| Scoring/privacy posture | Not implemented | [Overview](../Apps/FirePrivacyApp/OverviewView.swift) compares recorded contact counts and explicitly says its bars are not risk scores. No privacy, severity, confidence, or posture scoring exists. This was included in the original claimed Gate 1 scope. |
| Settings steps and choice trade-offs | Implemented as general guidance | [SettingsGuide](../Apps/FirePrivacyApp/GuidanceViews.swift) covers location, camera/microphone, photos, tracking, and Apple's report, with steps and trade-offs. Report-linked recommendations are generic. There is no complete category/action catalog, permission-state audit, or automatic change to another app's permissions. |
| Evidence chain and content-derived identifiers | Partial | Findings link to in-report observation UUIDs; [finding detail](../Apps/FirePrivacyApp/GuidanceViews.swift) opens those records. IDs are generated UUIDs, not source/content hashes. Successful observations retain no source line number/hash, source file hash, parser/normalization version, or stable cross-import provenance. The SHA-256 evidence linkage promised in the original security document is absent from the runtime model. |
| Encrypted local storage and device-only Keychain key | Implemented for one report; narrower architecture | [EncryptedReportStore](../Apps/FirePrivacyApp/EncryptedReportStore.swift) uses AES-GCM, a versioned envelope, a random 32-byte device-only unlocked Keychain key, complete file-protection attributes, atomic replacement, and backup exclusion. It encrypts the whole normalized report rather than each record, keeps one report rather than a session history, and has no key-rotation workflow. Hardware protection and locked-device behavior still require physical-device QA. |
| Raw-source minimization | Implemented default; optional retention absent | [ReportFileIO](../Apps/FirePrivacyApp/ReportFileIO.swift) reads the selected file in memory and does not persist raw bytes or modify the original. The original optional encrypted raw-copy setting is not implemented. No App Group or extension receives report data. |
| Explicit report export/share | Implemented as normalized JSON only | [Export envelope](../Apps/FirePrivacyApp/ReportFileIO.swift), [settings confirmation](../Apps/FirePrivacyApp/TrustSettingsViews.swift), and [system share sheet](../Apps/FirePrivacyApp/FirePrivacyApp.swift). Sensitive contents and destination behavior are disclosed; demo exports are labeled; temporary copies are cleaned up. There is no CSV/Markdown export, selectable redaction, or diagnostic-bundle export. |
| Delete all data and destroy the encryption key | Implemented with visible failure handling | [Store deletion](../Apps/FirePrivacyApp/EncryptedReportStore.swift), [model deletion](../Apps/FirePrivacyApp/AppModel.swift), and [store/UI tests](../Tests/FirePrivacyAppTests/EncryptedReportStoreTests.swift). Original Files documents and already-shared copies remain outside the app's control. Partial deletion is reported and retryable. Physical-device validation remains pending. |
| Trust Center and complete generated network ledger | Partial | [TrustCenterView](../Apps/FirePrivacyApp/TrustSettingsViews.swift) discloses actual local storage, sharing, and unavailable capabilities. It is static UI, not generated from `NetworkLedger.entries`; there is no detailed storage/session/consent/dataset inventory or contact history. The absent future services make no requests in this app. |
| Hostile-input handling | Implemented for supported fields | [Parser](../Sources/FirePrivacyCore/ReportImporter.swift) bounds file/line/record/nesting/string/collection sizes, rejects duplicate keys and invalid UTF-8, quarantines bad records, and rejects unsafe displayed identifiers/hosts. [Core tests](../Tests/FirePrivacyCoreTests/ReportImporterTests.swift) exercise those paths. There is no `UntrustedText` module; unsafe supported text is rejected rather than broadly sanitized, and unsupported owner/context/model fields are not retained. |
| iOS 26 privacy-preserving URL filtering | Not implemented | No Network Extension target, URL-filter manager/control extension, signed filter dataset, Bloom prefilter, PIR/OHTTP/Privacy Pass service, or safe-mode state machine is wired into the current project. [Trust Center](../Apps/FirePrivacyApp/TrustSettingsViews.swift) says filtering is not included. API availability, capabilities, service design, and Apple approvals need separate implementation/validation. |
| Safari content blocking and optional encrypted DNS | Not implemented | No current Safari extension, blocker rules, DNS configuration, or protection preferences exist. These appear in the earlier branch's layout/release gates, not in the candidate's [targets](../Package.swift). |
| On-device AI explanation and optional user-run endpoint | Not implemented | No Foundation Models adapter, advisor coordinator, endpoint pairing/TLS pinning, structured advisory input, grounding/output validator, mode selector, fallback/off switch, or preview/send consent exists. Descriptive text is authored locally in [PrivacyReport.findings](../Sources/FirePrivacyCore/PrivacyReport.swift). Private Cloud Compute is also absent. |
| Consent receipts and optional-service controls | Not implemented | Export has a user confirmation, but there is no persisted receipt system, dataset-update consent, model-endpoint consent, protection consent, or consent revocation inventory. Ordinary share confirmation is not the original `ConsentKit` concept. |
| Signed dataset updates and declarative rules | Not implemented | No Ed25519 dataset verification, digest/schema/expiry/revocation/rollback checks, updater transport, rule schema/change log, or trust-anchor update procedure is present in current app code. Signing checks in release scripts concern Apple's app build and are not a replacement for runtime knowledge-base/filter verification. |
| Managed edition: flow attribution, allow/drop, MDM enforcement | Not implemented | No supervised-device edition, managed filter, or MDM policy integration exists. These were explicitly separate from the consumer edition in the original README. |
| Honest platform/accuracy limits | Implemented in current wording and design | [Evidence](../Apps/FirePrivacyApp/EvidenceViews.swift), [guidance](../Apps/FirePrivacyApp/GuidanceViews.swift), and [Trust Center](../Apps/FirePrivacyApp/TrustSettingsViews.swift) distinguish contact from transmission, history from current permission, and unknown owner from danger. There is no installed-app enumeration, SDK disabling, other-app Settings deep link, encrypted-payload inspection, or claim that protection is active. These limits are intentional boundaries, not missing features to add. |

## Validation and audit follow-up

The implementation and validation statuses must stay separate. [VALIDATION.md](VALIDATION.md) records 34 passing portable XCTest cases and a prior successful native iPhone/iPad run for `d44a996`; it also identifies later changes awaiting a fresh native run. Real current Apple exports, hardware Data Protection/locked-device behavior, accessibility on physical devices, signed distribution, upload, and Apple approval are still separate release checks.

Two UI gaps were found during this audit at `e70799a`:

1. Canonical network records use `timeStamp`; the importer retains it as `timestamp`/`timestampText`, but the network evidence card's “Last recorded” row read only `lastTimestamp`/`lastTimestampText`. It could therefore say “Not included” when the export contained the time.
2. The network card labeled `accessType` as “Recorded context,” although its value was the record type `networkActivity` and the exported website `context` was not retained.

Both corrections are present in the follow-up working tree: an appropriate canonical-timestamp fallback, preservation of displayed original timestamp text, and the accurate “Record type” label. These UI changes await the next native validation run. They do not add retention of the discarded website-context field or expand the supported report schema.

The next completeness work should be selected explicitly from this matrix. A first App Store release can truthfully ship the local report MVP while the broader concepts remain unfinished, provided its listing, in-app disclosures, and privacy claims describe that actual build. Completing this audit or preparing signing automation does not establish that all original concepts are implemented or that Apple has accepted the app.
